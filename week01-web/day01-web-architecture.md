# Day01 Webアーキテクチャ

1.ブラウザでURLを入力してからページが表示されるまでの流れ
・DNSサーバーにアクセスしてウェブサイトにあるサーバーのアドレスを探す。
・ブラウザがサーバーにHTTPリクエストを送信して、ウェブサイトのコピーをクライアントに送るよう求める。
　これらはTCP/IPを使用してインターネット経由で行う。
・サーバーがリクエスト承認すると"200 OK"のメッセージを送って、Webサイトのファイルをパケットでブラウザに送信する。
・ユーザーに表示する。

2.GET・POST・PUT・PATCH・DELETEの違いを説明
GET　指定したURLの情報を取得。
POST　新しい子リソースの作成。201 Created　SNS投稿とか
PUT　リソースの更新　こんにちは→こんばんは。リソースの作成　wiki作成とか　
PATCH　リソースの部分的な変更　ログイン状態を変更するとか？
DELETE　リソースの削除

3.HTTPステータスコード401・403・404・422・500の違い
401 アクセス権不正、未認証
403 認証されていないなどの理由でクライアントにコンテンツのアクセス権がなく、サーバーが適切なレスポンスの返信を拒否していることを示します。
404 リソースの不在　Not Found
422 リクエストは適正ですが、意味が誤っているために従うことができません。構文が違うとか
500 サーバー内部エラー。サーバー側で処理方法がわからない事態が発生

4.Cookieとセッションの違い
・Cookie　ウェブサイトによってウェブブラウザーを通じて訪問者のコンピューター上に残される小さな情報。ウェブサイトのウェブ体験を個人化するために使用
・セッション　クライアント固有の状態を維持
